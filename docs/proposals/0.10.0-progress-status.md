### PR1 scenario-by-scenario breakdown

| Scenario | What landed |
|---|---|
| `AUTH-PRINCIPAL-01` | New two-principal e2e tests both sides, proving `session_key(principal, clientId)` is the sole ownership key even when two principals share one raw stable client id. Required refactoring `agent-rs`'s WebSocket handshake into a standalone `AgentServer::accept_connection` so tests can drive it over in-memory duplex pairs instead of a live TCP port |
| `AUTH-REVOKE-01` | **New feature**, not just a test — neither agent had *any* runtime credential-revocation mechanism before this. Added `ClientCredentials.revoke/unrevoke/isRevoked` (Kotlin) and `AgentServer.revoke_principal/unrevoke_principal/is_principal_revoked` (Rust), re-checked on every connection attempt including a transport-grace resume. **Not wired to an operator trigger yet** — no dashboard route (Kotlin) or admin endpoint/signal handler (Rust) calls it; that's a separate follow-up |
| `LEASE-DISCONNECT-01` | Kotlin: existing test relabeled. Rust: new test against `Op::Disconnect`'s immediate (no-grace) release path |
| `LEASE-GRACE-01`, `LEASE-GENERATION-01`, `LIMIT-FRAME-01`, `LIMIT-STREAM-01` | Existing tests on both sides already proved the required outcome; wired into the adapters table with no code change |
| `LEASE-DUPLICATE-01` | Kotlin: existing e2e test relabeled. Rust: new e2e test exercising the real pre-upgrade HTTP 409 path (previously only the underlying registry primitive was tested) |
| `LIMIT-SLOW-01` | New tests both sides proving the outbound channel sheds (not blocks) on overflow — Kotlin via a stalled-client harness hook, Rust via a direct `try_send`-to-capacity test on the same `Outbound` channel type/constant the production event pump uses |
| `LIVENESS-01` | Existing tests both sides (writer-failure + stale-connection-probe) relabeled |
| `BIND-SECURITY-01` | Rust: existing test relabeled. Kotlin: new `MainTest.kt` — required making `Main.kt`'s `validateBind` `internal` (was `private`, untestable) |
| `SHUTDOWN-01` | Kotlin: new `AgentRunnerTest` case driving `stop()` while a lease is mid transport-grace. Rust: **documented as an honest proxy** — `agent-rs` has no fake/mock `btleplug` seam, so `disconnect_all`/`shutdown_signal` in `main.rs` cannot be unit-tested; the closest testable equivalent (`late_connect_after_connection_retirement_unwinds_radio_and_lease`) is used instead, with the fidelity gap documented in the scenarios doc |
| `RECOVERY-01` | Documented as **Kotlin-client-only** — the reconnect reconciliation state machine lives entirely in the Kotlin client SDK; there is no Rust client SDK in this repo to pair against |
